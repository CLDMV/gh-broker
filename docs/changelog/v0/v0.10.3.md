# gh-broker v0.10.3 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/0.10.3`

---

## Overview

v0.10.3 moves the `gh-broker` command and the installer into the TypeScript source tree and bundles them the same way as the daemon. Nothing changes for a global npm install: `sudo gh-broker install` and every `gh-broker otp` and `gh-broker agent` command behave as before. Installing from a checkout is now `sudo ./deploy/install.sh`.

---

## 🔧 Refactoring

### The command and installer are built from `src/` ([#167](https://github.com/CLDMV/gh-broker/pull/167))

The CLI and installer were plain JavaScript under `deploy/`, shipped unbundled next to the daemon bundle, with the package bin at `./deploy/cli.mjs`. npm strips the leading `./` from a bin path at publish time and printed `"bin[gh-broker]" script name deploy/cli.mjs was invalid and removed` on every release. Despite the wording, the bin was never actually removed.

They are now strict TypeScript in `src/cli/`, with the command's entry in `src/bin/gh-broker.ts`. tsup bundles the command to `bin/gh-broker.mjs` alongside `dist/index.mjs`, the same layout as `@cldmv/vitest-runner`. The package bin is `bin/gh-broker.mjs`, so the publish warning is gone. The CLI modules are measured by the same 100% coverage gate as the daemon.

`deploy/` now holds only the systemd unit, `install.sh` and its README, and of those only the unit ships. The package goes from about 780 kB to 671 kB unpacked.

### Installing from a checkout

The installer used to build `dist/` itself when it was missing. It is a build output now, so a checkout is built by `deploy/install.sh` instead:

- it installs Node.js 22 through nvm if there is no suitable `node`;
- it refuses a checkout owned by root;
- it builds as the checkout's owner, never as root, after removing any `dist/`, `bin/` or `node_modules/` with files a root-run `npm` left behind;
- it reinstalls dependencies when `package-lock.json` changed since the last install, and rebuilds on every run, so a pulled checkout never deploys a stale bundle;
- then it runs `bin/gh-broker.mjs install` with the same flags.

## Upgrade notes

- No breaking changes for a global install. Upgrade with `sudo npm install -g --prefix /usr/local --ignore-scripts @cldmv/gh-broker@latest` and `sudo gh-broker install`.
- From a checkout, `sudo node deploy/install.mjs` is gone. Use `sudo ./deploy/install.sh [agent-user] [flags]`, or `npm ci && npm run build` and then `sudo node bin/gh-broker.mjs install`.
