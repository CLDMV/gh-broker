# gh-broker v0.5.1 Changelog

**Release Date**: October 2026
**Release Type**: Patch

---

## Overview

v0.5.1 stops the installer from asking where credentials are stored when the install already has an answer. Upgrading no longer needs a keypress, and the broker itself is unchanged.

---

## 🐛 Bug Fixes

### The installer keeps the existing secrets backend ([#95](https://github.com/CLDMV/gh-broker/pull/95))

`deploy/install.mjs` asked "How should the PAT credentials be stored at rest?" on every interactive run, and only `--non-interactive` skipped it. It now works out the backend already in use: the provider recorded in the deployed config, otherwise encrypted `.cred` files (systemd-creds) or tokens in the secrets file. It logs `keeping existing backend: <name>` and carries on. A first install, or a state where both backends hold credentials and nothing is recorded, still prompts, and `--secrets-provider` still overrides. Six unit tests cover the detection.
