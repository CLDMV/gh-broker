# gh-broker v0.17.2 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/0.17.2`

## Overview

v0.17.2 stops `agent reconnect` (and `upgrade`'s last step) from typing a command a session can't run.

---

## 🐛 Bug Fixes

### A session on its own config folder only gets that folder's key ([#271](https://github.com/CLDMV/gh-broker/pull/271))

A session started with a `CLAUDE_CONFIG_DIR` reads that folder's `.claude.json` and ignores `~/.claude.json`. When that folder had no broker entry, reconnect still sent the key from `~/.claude.json`, and the session answered `MCP server "github" not found`, on every upgrade. Now the home file's key is used only for a session with no `CLAUDE_CONFIG_DIR`. Any other session with no key of its own is skipped, and the line names the folder and the fix:

```
… skipped (its CLAUDE_CONFIG_DIR /home/u/.claude-x is not a config folder the broker manages: sudo gh-broker agent sync u --claude-config /home/u/.claude-x)
```

A folder the broker does read but whose file has no entry says `has no broker MCP entry` instead. These are real skips, so the run exits 3.

Resolves [#270](https://github.com/CLDMV/gh-broker/issues/270).
