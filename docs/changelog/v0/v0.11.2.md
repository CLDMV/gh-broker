## 🐛 Bug Fixes

### `npm_scaffold` waits for npm's staged first publish (fixes [#211](https://github.com/CLDMV/gh-broker/issues/211), [#212](https://github.com/CLDMV/gh-broker/pull/212))

npm stages a new package's first publish. It answers the PUT with `202`, creates the package at once with its own `0.0.0-stage` version, and makes the real version live by itself shortly after (77 s when `@cldmv/slothlet-migrate` was created). Nothing needs approving. `npm_scaffold` read the registry once, straight after the `202`, so it didn't see `0.0.1-placeholder` yet and failed, telling the user to look for a staged package that needed no action. It also never reached the trusted-publisher step.

The verb now checks the registry every 5 s for up to two minutes. Once the placeholder is live it returns `needs_otp` for the trusted publisher, as before. If it still isn't live, the result is the new `status: "pending"` with `done: ["publish"]`, not an error: wait a minute and call again with a fresh code. A call that finds the package holding only npm's `0.0.0-stage` also returns `pending` and writes nothing. The broker never publishes `0.0.0-stage` itself; npm leaves it next to the placeholder after every staged first publish.

## Upgrade notes

- No breaking changes. Callers of `npm_scaffold` should treat `status: "pending"` like `needs_otp`: call again later with a fresh npm code. Upgrade with `sudo npm install -g --prefix /usr/local --ignore-scripts @cldmv/gh-broker@latest`, then `sudo gh-broker install`.
