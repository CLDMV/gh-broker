## 🐛 Bug Fixes

### `npm_scaffold` waits for npm's staged first publish (fixes [#211](https://github.com/CLDMV/gh-broker/issues/211); [#212](https://github.com/CLDMV/gh-broker/pull/212), [#215](https://github.com/CLDMV/gh-broker/pull/215))

npm stages a new package's first publish. It answers the PUT with `202`, creates the package at once with its own `0.0.0-stage` version, and makes the real version live by itself shortly after (77 s when `@cldmv/slothlet-migrate` was created). Nothing needs approving. `npm_scaffold` read the registry once, straight after the `202`, so it didn't see `0.0.1-placeholder` yet and failed, telling the user to look for a staged package that needed no action. It also never reached the trusted-publisher step.

Either version on the registry, npm's `0.0.0-stage` or our `0.0.1-placeholder`, means the package exists and its trusted publisher can be added. The verb now checks the registry every 5 s for up to two minutes and returns `needs_otp` for the trusted publisher as soon as either one shows. A later call that finds only `0.0.0-stage` goes straight to the trust step and never publishes a second placeholder. Only when neither shows within the wait is the result the new `status: "pending"` (with `done: ["publish"]`), not an error: wait a minute and call again with a fresh code. The broker never publishes `0.0.0-stage` itself; npm creates it for every staged first publish. It records no repository, so a package holding only that version is guarded by the scope and repo checks alone.

## Upgrade notes

- No breaking changes. Callers of `npm_scaffold` should treat `status: "pending"` like `needs_otp`: call again a minute later with a fresh npm code. Upgrade with `sudo npm install -g --prefix /usr/local --ignore-scripts @cldmv/gh-broker@latest`, then `sudo gh-broker install`.
