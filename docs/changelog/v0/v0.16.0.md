# gh-broker v0.16.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.16.0`

---

## Overview

v0.16.0 keeps agent MCP sessions working across a broker restart. The MCP entry now runs `gh-broker connect`, a bridge that redials the daemon and replays the session's handshake, instead of socat, so an `install` or `upgrade` no longer drops every session until someone types `/mcp reconnect`. The broker also keeps its own copy of node at `/usr/local/lib/gh-broker/node` for the service and the bridges, and stops managing `/usr/local/bin/node`. `agent reconnect --wait` now waits in the background instead of holding the terminal.

---

## ✨ Features

### MCP sessions survive a broker restart ([#253](https://github.com/CLDMV/gh-broker/pull/253))

Agent MCP entries now run `exec /usr/local/lib/gh-broker/node /usr/local/bin/gh-broker connect <socket>` instead of socat. When the daemon restarts, the bridge dials again with backoff, replays the session's `initialize` and `notifications/initialized` (swallowing the duplicate response), answers any request that was in flight with an error, and sends `notifications/tools/list_changed` so the client refetches its tools. Requests sent while the daemon is down are held, up to about 1 MiB in all, and go out once it's back. One that waits more than 30 seconds gets an error instead, so the client can retry. The daemon now declares `tools.listChanged`.

`gh-broker install` rewrites old socat entries and the interim `/usr/local/bin/node` form, and refuses before changing anything when the CLI binary is missing.

Resolves [#193](https://github.com/CLDMV/gh-broker/issues/193).

### The broker's own node ([#253](https://github.com/CLDMV/gh-broker/pull/253))

`install` and `upgrade` keep a root-owned copy of node at `/usr/local/lib/gh-broker/node`, in a root:root 0755 directory the service user can't write. The service unit and every bridge run it.

- **Which node:** the highest even (LTS) major at or above `engines.node`, taken from every `node` on PATH, then the system nvm (`$NVM_DIR`, `/usr/local/nvm`, root's `~/.nvm`), then the node running the installer. When none qualifies, it downloads the latest LTS from nodejs.org, checks the tarball against `SHASUMS256.txt`, and extracts only `bin/node`.
- **Only safe candidates:** a candidate is run or copied only if it is a root-owned ELF binary that nobody else can write, under root-owned directories all the way up to `/`. Root's nvm comes from the passwd entry, not `$HOME`, and relative PATH entries are ignored.
- **Later runs** replace the copy only with a strictly newer version, or when the copy is missing, broken, below the floor or an odd major. Same version means it stays. The copy is written to a temp file, checked to report the expected version, then renamed over, so running bridges keep the old binary until they restart.
- **`/usr/local/bin` is left alone.** The broker no longer writes `/usr/local/bin/{node,npm,npx}`. `deploy/install.sh` only fills them in on a box with no node at all. The old `pointNodeSymlinks`, which could delete a real node at `/usr/local/bin/node`, is gone.

### `agent reconnect --wait` waits in the background ([#249](https://github.com/CLDMV/gh-broker/pull/249))

Panes that are clear get `/mcp reconnect` right away. The ones blocked by typed text or a dialog go to a `gh-broker-reconnect-wait` systemd unit that retries only those panes (`journalctl -u gh-broker-reconnect-wait -f`). A new `--wait` replaces one still running, and `--foreground` keeps the old blocking behaviour. If the unit can't be started, it waits in the foreground as before.

Resolves [#248](https://github.com/CLDMV/gh-broker/issues/248).

## Upgrade notes

- `sudo gh-broker upgrade --wait 5m`. The upgrade writes the new MCP entries and the broker's node, then restarts the daemon.
- Sessions that are already running still use their old socat entry, so this one upgrade still needs the reconnect step (the `upgrade` reconnect, or `agent reconnect`). After that, restarts no longer drop them.
- Anything already at `/usr/local/bin/{node,npm,npx}` is left as it is.
