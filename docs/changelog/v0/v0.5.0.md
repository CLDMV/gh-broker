# gh-broker v0.5.0 Changelog

**Release Date**: October 2026
**Release Type**: Minor

---

## Overview

v0.5.0 adds two report verbs that answer fleet-wide questions in one call instead of one call per repo: `report_security_alerts` for open Dependabot, CodeQL and secret-scanning alerts, and `report_release_prs` for open release PRs and whether each has its changelog. Existing verbs behave as before, with one fix in how rate limits are recognised.

---

## ✨ Features

### `report_security_alerts` ([#91](https://github.com/CLDMV/gh-broker/pull/91))

Lists every open Dependabot, code-scanning (CodeQL) and secret-scanning alert for one repo or a whole owner. It reads the org-level alert endpoints in a handful of calls and falls back to a per-repo sweep for any alert type the token cannot read org-wide. Each alert is normalized to one shape with type-specific fields (package, patched version and manifest for Dependabot; rule and location for CodeQL; secret type and validity for secrets), sorted worst first. Secret values are never returned. Results carry `scope` (org or per-repo for each type) and `disabled` (repos where a type is off), and the usual `truncated` / `truncatedReason` when a cap or the rate limit is hit. An alert's state tracks the default branch, so one already fixed on `next` still reads open until it ships.

### `report_release_prs` ([#91](https://github.com/CLDMV/gh-broker/pull/91))

Finds every open release PR (label `release`: the `next` and `hotfixes` lines into `master`) for an owner and reports whether each one's per-version changelog file (`docs/changelog[s]/v<major>/vX.Y.Z.md`) exists on the release branch, as `ready`, `needs-changelog` or `unknown-version`. It costs one search call plus a few calls per release PR, and `onlyMissing` narrows the list to the ones that still need a changelog.

## 🐛 Bug Fixes

### A permission 403 is no longer mistaken for a rate limit ([#91](https://github.com/CLDMV/gh-broker/pull/91))

The shared REST client treated every `403` as throttling, so a "feature not enabled" answer (code scanning off on a repo) would have stopped a whole scan. A `403` now counts as a rate limit only when GitHub signals one: a `Retry-After` header, an exhausted `x-ratelimit-remaining`, or a rate-limit or abuse message. Everything else reaches the caller with its status. This also applies to `report_unlabeled` and `report_ci_status`. Dependabot's cursor pagination and the repo-listing helper moved into the shared client with it.
