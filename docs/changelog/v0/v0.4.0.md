# gh-broker v0.4.0 Changelog

**Release Date**: September 2026
**Release Type**: Minor
**Branch**: `release/0.4.0`

---

## Overview

This release adds two report-style custom verbs — `report_unlabeled` and `report_ci_status` — plus a new way for the broker to enrich a proxied tool's response in place, and fixes three real bugs found while building and deploying them. Nothing about this release is breaking: every addition is a new verb or an opt-in parameter, and existing callers see no behavior change.

The headline capability is CI visibility without per-call log fetches: `report_ci_status` (and the same logic layered onto a normal `pull_request_read`) answers "does this PR have failing checks" at whatever detail level the caller asks for — counts only by default, escalating to which job failed, which step failed, and finally a tail of the failing job's actual log — and only ever pays for that detail on runs that are genuinely failing. Verified against a real failing PR (`CLDMV/droidsock#35`): correct pass/fail classification across five jobs (including three cancelled matrix legs), correct per-step failure detail, and a real log tail that surfaced the actual root cause (an `npm ERESOLVE` peer-dependency conflict) with no further digging required.

## ✨ Features

### `report_unlabeled` — issues/PRs missing labels, one repo or every repo an owner has (#57)

Composes the already-allowlisted `list_issues`/`list_pull_requests` (plus an org-repo listing when `repo` is omitted) into a single report of unlabeled issues and/or PRs. Bounded by `maxRepos`/`perRepoLimit`/`maxApiCalls`, with a rate-limit floor read from the token's own `x-ratelimit-limit` header (not a hardcoded assumption about which token type is in use) so it backs off before GitHub does. Draft PRs are excluded by default (`includeDrafts` to override). Hitting a cap or the rate limit returns `truncated: true` with whatever was already found, rather than discarding partial results.

### `report_ci_status` — tiered CI health for a PR, or every open PR in a repo (#61, #64)

Reports pass/fail/pending counts by default (tier 0), escalating on request to which run/job failed (tier 1), which step inside that job failed (tier 2), and a tail of the failing job's log (tier 3). Detail beyond tier 0 is only ever fetched for jobs that are actually failing, so a healthy PR costs exactly one call regardless of the requested verbosity. Tier 3 calls the hosted MCP's own `get_job_logs` tool (`failed_only: true` fetches every failing job in a run in one call) rather than a hand-rolled REST fetch — one call per failing run, not per job (#64).

### `pull_request_read` gets an inline `ciVerbosity` parameter (#61)

A normal `pull_request_read` (`method: "get"`) can now carry CI status inline by passing `ciVerbosity` (0–3, same tiers as `report_ci_status`) and an optional `logLines`. This is the first tool the router's new **augment** dispatch mode powers: forward to the hosted MCP like a plain proxy, then post-process the result — gh-broker's own MCP contract for a proxied tool is not required to match the hosted MCP's shape verbatim. Opt-in only: omitting `ciVerbosity` is a byte-identical forward, so existing callers are unaffected.

## 🐛 Bug Fixes

### `npm run dev` crashed outright (#63)

`node --experimental-strip-types` — the project's own `dev` script — rejects TypeScript constructor-parameter-property syntax, which `Router` and `AppAuth` both used. Invisible to `typecheck`/`build`/`test` since `tsc` and `esbuild` transform the code rather than only stripping types. Fixed in both places it appeared; verified against the real `dev` command, which now reaches `listening` where it previously crashed before any application code ran.

### Installer left root-owned `dist/`/`node_modules/` in the checkout (#63)

The installer requires root, and its build-if-needed step ran `npm ci`/`npm run build` inside the repo checkout itself — not just the deploy target, which is chowned correctly elsewhere. That left build output owned by root in the operator's own working tree, breaking their next plain `npm run build` with `EACCES`. Fixed at the root cause: the build now runs via `sudo -u '#<uid>'`, with the uid read directly from the install script's own file ownership — no separate "agent user" concept needed, and no `chown` anywhere (not cross-platform, and unnecessary once nothing is ever created with the wrong owner to begin with). Detects and rebuilds a stale `dist/`/`node_modules/` left by an older version of this script, so re-running the installer is self-healing with no manual cleanup step.

### Rate-limit floor was a hardcoded guess (#57)

`report_unlabeled`'s proactive rate-limit backoff was a flat `100` with no derivation from GitHub's actual limit — wrong for any token whose real quota differs from a 5,000/hr PAT. Now reads `x-ratelimit-limit` off every response and floors at 2% of that, with an absolute minimum for low-limit tokens. `report_ci_status` shares the same rate-limit/call-budget module (`rest-client.ts`, extracted once a second verb needed the identical logic).

## 🔧 CI & tooling

- Extracted the rate-limit-floor + call-budget machinery shared by `report_unlabeled` and `report_ci_status` into `src/verbs/rest-client.ts`.
- `router.ts` gained a third dispatch mode, `augment`, alongside the existing `custom` (fully local) and plain-`forward` paths — logged in the audit trail the same way as the other two.
