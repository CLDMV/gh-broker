# gh-broker v0.12.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.12.0`

---

## Overview

v0.12.0 publishes the broker's core as a library. A host other than the daemon can now import `@cldmv/gh-broker` (or `@cldmv/gh-broker/core`), build a broker from its own config and token resolver, and call tools with the same policy, OTP and dispatch code the daemon runs. This finishes the library split tracked in #175; v0.11.0 carried the earlier steps.

The daemon behaves the same as v0.11.2: same tools, tokens, OTP gate, audit rows, CLI output and on-disk state. The service still runs `dist/index.mjs`, and `engines.node` stays `>=22.0.0`.

## ✨ Features

### `invoke`, the library's entry point ([#217](https://github.com/CLDMV/gh-broker/pull/217))

`createBroker(config, options)` returns two bound functions:

- `invoke(name, args, ctx)` runs one tool call: policy, availability, input validation, OTP approval, owner resolution, token resolution, then dispatch. It returns `{ result }` (JSON-safe, with `mcpTarget` when the call was forwarded) and builds no MCP content blocks; wrapping the result is the host's job.
- `run(request, args, ctx)` is a thin driver adapter over `invoke`. The request is `{ op: "mcp", target }` for a tool forwarded to GitHub's hosted MCP, or `{ op: "graphql" | "rest", tool }` for a local verb, and the `op` has to match what the manifest says the tool is.

Errors are an `InvokeError` with a `code` and a message that never carries a token, seed or path. The codes: `unknown-tool`, `disabled`, `unavailable`, `bad-args`, `bad-request`, `otp-required`, `otp-refused`, `no-owner`, `no-access`, `no-upstream` and `not-supported`. Verb and upstream errors pass through unchanged.

The host supplies the OTP check as `ctx.approve(tool, person, args, signal)`. It is required: a gated tool called without it fails with `otp-required` and nothing runs. The library has no OTP gate, clock, secrets, filesystem or sockets of its own.

`ctx.signal` and an optional `ctx.timeoutMs` reach every outbound call: the approve hook, the token resolver, Octokit, the MCP transport and the npm registry requests. `perCallUpstream(url)` is the library's forwarder to the hosted MCP. It opens a fresh connection per call and keeps nothing token-shaped afterwards; the daemon keeps its pooled upstream.

Hosts get the strict policy by default: config can add an OTP requirement but never remove one, read tools stay read, and tools the manifest doesn't know don't exist. The daemon passes the permissive policy explicitly, so `config.json` keeps its authority there. The router now takes the OTP gate and the GHCR service as injected dependencies. The GHCR verbs and `otp_status` stay host-only, and `invoke` refuses them with `not-supported`.

### The package exports the library ([#219](https://github.com/CLDMV/gh-broker/pull/219))

`package.json` has an `exports` map: `.` and `./core` both point at `dist/core/index.mjs`, with bundled types in `types/core/index.d.ts`, plus `./package.json`. `main` and `types` point at the library too. The barrel exports `createBroker`, `InvokeError`, `perCallUpstream`, the ctx/result/driver types, the manifest and policies, the catalog and the pure verbs.

The OTP limit settings moved into `src/core/`, which removes the last import from the library into daemon code, and the old store-based `buildCatalog` signature is gone. The build now wipes `dist/`, `types/` and `bin/` once before tsup runs, because tsup builds its configs concurrently, and the installer skips `dist/core/` when it copies the daemon to `/opt`.

Resolves [#175](https://github.com/CLDMV/gh-broker/issues/175).

## Upgrade notes

- No changes for the daemon. Upgrade with `sudo npm install -g --prefix /usr/local --ignore-scripts @cldmv/gh-broker@latest`, then `sudo gh-broker install`.
- The package root used to point `main` at the daemon's `dist/index.mjs`. It now resolves to the library, and the `exports` map closes deep imports such as `@cldmv/gh-broker/dist/index.mjs`. Run the daemon through the `gh-broker` command or the systemd unit, not by importing the package.
