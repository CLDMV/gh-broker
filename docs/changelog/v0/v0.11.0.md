# gh-broker v0.11.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.11.0`

---

## Overview

v0.11.0 lets `npm_scaffold` set up a package published from a subfolder, or one that isn't on the default branch yet. It also carries the first big steps of splitting the broker's core into a library (#175): the OTP gate now runs on `@cldmv/lib-otp`, the tools are declared in a manifest, credentials reach the router through an injected token resolver, and the library code lives in `src/core/`.

The daemon behaves the same as v0.10.7 for everything except `npm_scaffold`'s new arguments: same tools, tokens, OTP gate, audit rows, CLI output and on-disk state.

---

## ✨ Features

### `npm_scaffold` checks a `package.json` in a subfolder, on another branch ([#205](https://github.com/CLDMV/gh-broker/pull/205))

Two optional arguments:

- `path`: the repo-relative `package.json` that names the package, e.g. `packaging/slothlet-migrate/package.json`. Defaults to `package.json`.
- `ref`: the branch to read that `package.json` and the publish workflow from, e.g. `next`. It must be an existing branch of the repo. Defaults to the repo's default branch.

A satellite package's `package.json` often only reaches the default branch with the release whose publish run already needs the trusted publisher, so it can now be scaffolded from `next`. All the other checks are unchanged.

Fixes [#206](https://github.com/CLDMV/gh-broker/issues/206).

### The core library takes shape ([#202](https://github.com/CLDMV/gh-broker/pull/202), [#203](https://github.com/CLDMV/gh-broker/pull/203), [#204](https://github.com/CLDMV/gh-broker/pull/204))

Part of [#175](https://github.com/CLDMV/gh-broker/issues/175). None of this is exported yet, and the daemon runs on it unchanged.

- The tools the broker knows are declared as data in a manifest. Two policies apply config over it: permissive, which the daemon uses (`config.json` stays authoritative, and widening a tool only logs a startup warning), and strict, the library default (never looser than the manifest or the daemon).
- The router gets every token through an injected token resolver. The daemon's resolver honours the owner and mode, and refuses an owner with no credentials. The OTP gate and the GHCR verbs are injected the same way.
- The library code moved into `src/core/`, and a test fails if anything there imports daemon code. The old import paths still work.
- An invalid OTP seed now fails with `OTP_SEED_INVALID` instead of a raw `TypeError`.

## 🔧 Refactors

### The OTP gate runs on `@cldmv/lib-otp` ([#199](https://github.com/CLDMV/gh-broker/pull/199))

The code check, seed generation, otpauth URI and the lockout state machine now come from `@cldmv/lib-otp` 0.1.0. Refusal texts, audit rows, the state file and the `gh-broker otp` output are byte-identical. Two edge cases changed along the way: `gh-broker otp unlock` with an empty `SUDO_USER` now falls back to `root` the way an unset one does, and `config.otp.lockoutSeconds` is capped at the largest value a date can hold, with an error that names the key.
