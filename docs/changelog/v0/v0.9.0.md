# gh-broker v0.9.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.9.0`

---

## Overview

v0.9.0 adds three read-only report verbs. Each one replaces a step the release and fleet-update skills used to do by hand with lockfile reads and PR lists. `report_alert_status` says where each open Dependabot alert's fix stands. `report_release_changes` returns the source material for a release's changelog. `report_dependents` finds every repo that declares an npm package, `dev` branches included. `list_pull_requests` also gains the opt-in `ciVerbosity` that `pull_request_read` already had.

The npm package can now install itself: `sudo npx @cldmv/gh-broker <agent-user>` runs the same installer as a checkout, from a prebuilt bundle. This also fixes the v0.8.0 tarball, which shipped sources and tests and had a `gh-broker` command that couldn't run.

Nothing is breaking. The new verbs are read-only, use the read PAT and appear only when they're listed in `config.tools`. Every existing verb and proxied tool behaves as in v0.8.0.

## ✨ Features

### `report_alert_status`: where each Dependabot alert's fix stands ([#142](https://github.com/CLDMV/gh-broker/pull/142))

`report_security_alerts` says which alerts are open. `report_alert_status` says what has to happen for each one, for one repo, a list of repos, or every repo with an open Dependabot alert. Closes [#100](https://github.com/CLDMV/gh-broker/issues/100).

- **One bucket per alert**, checked in order so the bucket is the furthest the fix has got: `released-still-open` (the default branch already resolves a patched version, so the fix didn't take), `fixed-on-next` (`next` or `hotfixes` is patched, waiting for a release), `open-pr`, `closed-unmerged` and `no-pr`.
- **Lockfiles.** For npm alerts it reads the lockfile nearest the alert's `manifest` on the default branch, `next` and `hotfixes`, walking up the directory tree so a workspace package resolves to the workspace lockfile. `package-lock.json`, `npm-shrinkwrap.json`, `pnpm-lock.yaml` and `yarn.lock` are all understood. Each lockfile is read once per commit and is capped by `maxLockfileBytes`.
- **PR history.** Open PRs that bump the package are linked, with the `hotfix-redirect/pr-<n>` twin when one exists. Closed PRs note `supersededBy` when a later PR for the package merged. Each repo row also carries a `dependabot.looksPaused` hint.
- The usual `maxApiCalls`, rate-limit floor and `truncated` / `truncatedReason` handling apply. Repos a cap stopped are listed in `pending`.

### `report_release_changes`: source material for a release's changelog ([#141](https://github.com/CLDMV/gh-broker/pull/141))

For one release PR, `report_release_changes` returns the PRs that actually ship and the release's net facts. Closes [#101](https://github.com/CLDMV/gh-broker/issues/101).

- **Scoped by net change.** It starts from the release PR's commits, using the same extraction as `report_release_prs` `analyze`. It then drops PRs that shipped in an earlier release or are named in the previous changelog, and PR/revert pairs inside the range. These are listed in `excluded` with a reason.
- **Detail levels.** `detail` is `titles`, `summaries`, `files` or `diff`, with per-PR and total caps. Lockfiles, `dist/` and `types/` patches are skipped. `prs` limits the deep detail to a few PRs.
- **Grouped by section** (`breaking`, `features`, `fixes`, `security`, `ciTooling`, `documentation`, `dependencies`, `ungrouped`), from the title's type and the labels. Breaking hints come from `!`, `BREAKING CHANGE` and `semver: major`.
- **`documented`** marks PRs the version's changelog already mentions, so one call serves both a first draft and an update.
- **Net facts.** The `net` block has `package.json` deltas, the direct dependencies with their locked versions on both sides, and file totals. `hotfixes` lists interim hotfix releases that aren't on the head branch. `skeleton: true` returns a changelog in the per-version template with one entry per PR and no prose.

### `report_dependents`: every repo that declares a package ([#140](https://github.com/CLDMV/gh-broker/pull/140))

`report_dependents` finds every non-archived, non-fork repo an owner has that declares an npm package in `dependencies`, `devDependencies` or `peerDependencies`. That list is the starting point for a fleet-wide bump. Closes [#102](https://github.com/CLDMV/gh-broker/issues/102).

- **Default branches.** An org code search finds candidates. Each one is verified against its `package.json` files, including workspace members, which are reported with `member` set to their directory. Versions are resolved from `package-lock.json` or `pnpm-lock.yaml`, each repo gets its flow tier (`v4` / `dev-trunk` / `non-v4`), and `latest: true` marks declarations that are behind the published version.
- **`dev` branches.** Code search only indexes default branches, so dev-trunk repos were invisible to it. A second pass lists the owner's repos over GraphQL and reads each `dev` branch that differs from the default branch: one tree call, every `package.json` outside `node_modules`, and the lockfile. Entries carry `branch`. A `dev` whose root version is below the default branch's is treated as abandoned: it is skipped and listed in `abandonedDev`. `devBranches: false` turns the pass off.
- Capped by `maxRepos` (both passes together), `maxFileBytes` and `maxApiCalls`, with the usual truncation reasons.

### `ciVerbosity` on `list_pull_requests` ([#139](https://github.com/CLDMV/gh-broker/pull/139))

`list_pull_requests` now accepts the `ciVerbosity`, `logLines` and `maxDetail` parameters that `pull_request_read` already takes, and adds a `ci` field to each listed PR. Detail goes to the first `maxDetail` PRs (default 10, hard cap 50), and the whole list shares one call budget and the rate-limit floor. Without `ciVerbosity` the call is forwarded unchanged. Closes [#120](https://github.com/CLDMV/gh-broker/issues/120).

### Install from npm ([#137](https://github.com/CLDMV/gh-broker/pull/137))

The package's `bin` is now the installer, so `sudo npx @cldmv/gh-broker <agent-user>` installs or upgrades the broker with the same flags as `sudo node deploy/install.mjs` from a checkout. The tarball ships a prebuilt `dist/`, so there is nothing to build.

## 🐛 Bug Fixes

### The npm tarball ships only runtime files ([#137](https://github.com/CLDMV/gh-broker/pull/137))

The v0.8.0 tarball included `src/`, `tests/`, `docs/` and `tsconfig.json`. Its `bin` entry pointed at a bundle with no shebang, so the `gh-broker` command it created couldn't run. `files` now limits the package to `dist/`, `deploy/` and the two config files, and the `bin` is the installer.

## 🔒 Security & supply chain

- `eslint` and `@eslint/markdown` still pull vulnerable `minimatch` 10 and `katex` 0.16. They're now overridden to the patched majors (`minimatch` `^11.0.3`, `katex` `>=0.19.1 <1.0.0`). Both are dev-only. ([#137](https://github.com/CLDMV/gh-broker/pull/137))
