# gh-broker v0.3.0 Changelog

**Release Date**: September 2026
**Release Type**: Minor
**Branch**: `release/0.3.0`

---

## Overview

v0.3.0 replaces gh-broker's deploy tooling with a single idempotent **Node installer** that handles both first install and upgrade, makes credential storage a **backend the operator chooses at install** (host-bound `systemd-creds`, encrypted at rest, by default; or a portable plaintext file), and puts **platform-neutral path resolution** under the daemon.

Nothing on the broker's runtime request path changed — owner/mode → PAT routing, the default-deny allowlist, the custom review-thread verbs, and the token-free config model all behave exactly as in v0.2.x. This release is entirely about how the daemon is **deployed, upgraded, and how its PATs are stored, migrated, and rotated**. It also carries a large batch of installer/secret-handling hardening and the deploy-model documentation.

The immediately preceding release, **v0.2.5**, shipped the `npm_and_yarn` security group bump (#40) as a hotfix; v0.3.0 builds on top of it.

## ✨ Features

### One Node installer — first install and upgrade in a single command (#45)

`deploy/install.mjs` replaces the old shell scripts (`launch.sh`, `provision.sh`, `deploy-app.sh`). A single idempotent command does first install **and** upgrade: it regenerates the deployed config by **merging shipped defaults over the current config** (never a blind overwrite, so an operator's settings survive an upgrade while new defaults are picked up), deploys the built `dist/`, installs the hardened unit, and runs a post-deploy MCP smoke test. It is interactive by default and **fully non-interactive** via CLI flags (`--agent-user`, `--secrets-provider`, `--secrets-file`, `--create-agent-user`, `-y/--non-interactive`) or `GH_BROKER_SECRET_<NAME>` environment variables for unattended runs.

### Operator-chosen secret backend, behind a provider seam (#45)

At install the operator chooses how the PATs are stored at rest: **`systemd-creds`** (default — host-bound, encrypted, delivered into `$CREDENTIALS_DIRECTORY` via a `LoadCredentialEncrypted` unit drop-in) or a **portable plaintext `file`** (`0640 root:gh-broker`, platform-neutral). A `config.secrets.provider` seam and platform-neutral path resolution (`--config` / `GH_BROKER_CONFIG` / `GH_BROKER_SECRETS` → platform config dir → default) back both, and the daemon exposes `--print-paths` and `--check` so the installer resolves paths and validates the config through the daemon itself (one resolver, no drift).

### In-place credential migration and rotation (#45)

Existing `systemd-creds` tokens are **auto-migrated** on upgrade — the installer decrypts and re-uses them without re-prompting when they're detectable. A re-run **rotates** a credential when a new value is supplied (via `--secrets-file` or `GH_BROKER_SECRET_<NAME>`), while a plain re-run keeps the existing encrypted cred as-is.

### The unit runs node via a maintained symlink (#43, #45)

The systemd unit no longer hardcodes a versioned node path. #43 first resolved node from the system-wide nvm `default` alias; v0.3.0 finalizes this as the unit running **`/usr/local/bin/node`** (a maintained symlink), so bumping node needs no unit edit and the CLI and service share one indirection.

## 🐛 Bug Fixes

### Secret, credential, and installer input handling hardened (#45)

A batch of correctness and safety fixes across the installer and secret layer:

- **Credential names** are constrained to a safe charset (`[A-Za-z0-9._-]`, rejecting `.`/`..`) on both the daemon and installer sides, so a `cred:` name can't traverse outside `$CREDENTIALS_DIRECTORY` / the secrets file or produce a malformed root-written systemd drop-in.
- **File-provider tokens** strip a single trailing newline (matching `systemd-creds`), so a copy/pasted token isn't silently mismatched at auth time, and a newline-only value is rejected as empty.
- **Config and `--secrets-file` validation** reject arrays (which `typeof === "object"` otherwise accepts) and empty values; `config.secrets.path` is rejected unless the provider is `file` (it would otherwise be silently ignored under `systemd-creds`).
- **CLI flag parsing** rejects a missing/flag-shaped value (so `--agent-user --secrets-provider file` can't mis-parse the flag as the username), and `--config` without a path value fails fast rather than silently falling back to the default.
- **Ownership operations fail fast** when a uid/gid can't be resolved, instead of silently leaving `/etc/gh-broker` / `/opt/gh-broker` mis-owned or running `chown NaN:NaN`.
- **Switching to `systemd-creds`** now zero-overwrites and removes any leftover plaintext secrets file, so "encrypted at rest" isn't undermined by a stale file.
- The interactive prompt **fails with guidance** (use `--secrets-file`/env) when asked for a multi-line App PEM, rather than capturing only its first line.
- The post-deploy **smoke test waits for the socket** instead of failing on the first connect during the daemon's startup network I/O.

## Upgrade notes

- **No runtime or API change** — the broker's request routing, default-deny allowlist, custom verbs, and token-free config model are identical to v0.2.x. There is nothing to change in how an agent talks to the broker.
- **The deploy process changed.** Install and upgrade with `sudo node deploy/install.mjs` (see `docs/deploy-architecture.md` and `deploy/README.md`); the old `launch.sh`, `provision.sh`, and `deploy-app.sh` are removed. Existing `systemd-creds` installs **auto-migrate** on upgrade — re-run the installer, no token re-entry needed.
- The secret backend is chosen at install; `systemd-creds` (encrypted at rest) remains the default.
