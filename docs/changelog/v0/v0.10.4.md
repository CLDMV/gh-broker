# gh-broker v0.10.4 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/0.10.4`

---

## Overview

v0.10.4 makes the broker report its real version. Until now the MCP handshake always said `0.1.0`, whatever release was installed, so there was no way to tell from a connection what a box was running. The release also renames the type-check script to the fleet's `types:check`.

The only runtime change is the version string the broker reports. Tools, routing and the installer behave as before.

---

## 🐛 Bug Fixes

### The handshake reports the installed version ([#173](https://github.com/CLDMV/gh-broker/pull/173))

`initialize` answered with `serverInfo.version: "0.1.0"` on every release, so a box on v0.10.3 still identified itself as 0.1.0. It now reports the version from `package.json`. The version is compiled into `dist/index.mjs`, because the service directory `/opt/gh-broker` only holds `dist/` and has no `package.json` to read at run time.

The client info the broker sends to GitHub's hosted MCP server when it connects upstream had the same hardcoded `0.1.0` and now carries the package version too.

Fixes [#172](https://github.com/CLDMV/gh-broker/issues/172).

---

## 🔧 CI & tooling

### `typecheck` is now `types:check` ([#170](https://github.com/CLDMV/gh-broker/pull/170))

The type-check script is renamed to `types:check`, the name the other CLDMV repos use, and the `test:types` alias is gone. `npm run build` and CI's `type_check_command` call `types:check`. Anything that ran `npm run typecheck` or `npm run test:types` needs the new name.

`tsconfig.json` now sets `rootDir: "."` and `resolveJsonModule`, so source files can import `package.json` ([#173](https://github.com/CLDMV/gh-broker/pull/173)). The build still type-checks only `src/`.

## Upgrade notes

- No breaking changes. Upgrade with `sudo npm install -g --prefix /usr/local --ignore-scripts @cldmv/gh-broker@latest`, then `sudo gh-broker install`. The second command alone redeploys the package that's already installed, not the new one.
- After the upgrade, an MCP client's `initialize` shows `0.10.4` in `serverInfo.version`.
