# gh-broker v0.4.2 Changelog

**Release Date**: October 2026
**Release Type**: Patch

---

## Overview

v0.4.2 patches the three transitive dependencies behind four open Dependabot alerts, bumps the MCP SDK and the test runner, and fixes how the CI mirror job reports the required check. The broker's behavior is unchanged.

---

## 🔒 Security & supply chain

### Patched transitive dependencies ([#90](https://github.com/CLDMV/gh-broker/pull/90))

A lockfile-only update moves three packages that the MCP SDK pulls in to their patched releases:

- `ip-address` 10.7.0 to 10.7.3, which fixes [alert 18](https://github.com/CLDMV/gh-broker/security/dependabot/18) (a long input could stall the process) and [alert 19](https://github.com/CLDMV/gh-broker/security/dependabot/19) (`isInSubnet` could admit an address from a different address family).
- `fast-uri` 3.1.7 to 3.1.8, which fixes [alert 20](https://github.com/CLDMV/gh-broker/security/dependabot/20) (inconsistent host case normalization).
- `hono` 4.13.5 to 4.13.12, which fixes [alert 21](https://github.com/CLDMV/gh-broker/security/dependabot/21) (the `hono/jsx` unescaped-string XSS).

None of them is a direct dependency. The broker is a local stdio proxy, so exposure was low, but the alerts are now closed on the release branch.

## 🔧 CI & tooling

### The required-check mirror no longer skips ([#87](https://github.com/CLDMV/gh-broker/pull/87), [#89](https://github.com/CLDMV/gh-broker/pull/89))

The `✅ Required PR Check` mirror job in `ci.yml` was skipped on in-repo feature PRs. GitHub treats a skipped required check as satisfied, and it never evaluates a skipped job's `name:`, so the PR showed the raw expression as a check name. The job now runs on every path with `if: always()`. On an in-repo PR it reports under a readable, non-required name (`⏭️ Required PR Check (reported by the push run)`) and passes as a no-op, while the push run still posts the required name. It still waits for the full test matrix through `needs: ci`.
