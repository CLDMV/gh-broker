# gh-broker v0.10.2 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/0.10.2`

---

## Overview

v0.10.2 fixes agents whose Claude sessions read a config folder other than `~/.claude.json`. Such a session (one started with `CLAUDE_CONFIG_DIR`) was left pointing at the shared socket that v0.10.0 removed, so the GitHub MCP failed to connect. `install` and `agent sync` now write the MCP entry into every Claude config folder an agent uses.

The package is also smaller: it no longer ships the 1.4 MB source map, and the bundle is now built minified with tsup. The Node.js floor goes back down to 22.0.0.

---

## 🐛 Bug Fixes

### The MCP entry reaches every Claude config folder an agent uses ([#164](https://github.com/CLDMV/gh-broker/pull/164))

Claude Code reads `$CLAUDE_CONFIG_DIR/.claude.json` when that variable is set, and the installer only ever wrote `~/.claude.json`. After the v0.10.0 socket change, a session using `~/.claude-secondary` or a similar folder kept the old `/run/gh-broker/gh-broker.sock` entry and couldn't connect. Fixes [#163](https://github.com/CLDMV/gh-broker/issues/163).

For registered agents only, `install`, `agent add`, `agent sync`, `agent remove` and `agent list` now also cover:

- every `~/.claude*` folder in the agent's home;
- the `CLAUDE_CONFIG_DIR` of each running `claude` session, when it is inside the agent's home;
- folders saved with `--claude-config`, for a config folder outside the home. Use `agent add|sync <user> --claude-config <dir>` or `install --claude-config <user>:<dir>`. Saved folders are kept under `claudeConfigDirs` in `/etc/gh-broker/config.json`, so every later sync updates them.

Outside `~/.claude.json`, root only edits a `.claude.json` that already exists, in a real directory (not a symlink) that the agent owns. The folder is opened once and the file is edited through that open descriptor, so the path can't be swapped mid-edit. A folder that doesn't qualify is skipped with a warning and doesn't fail the run. `agent list` shows the status of each folder, and `agent remove` cleans them all.

Two smaller changes come with it:

- The `agent` subcommands reject unknown flags instead of ignoring them.
- The agent commands now write `config.json` atomically, since they write to it too now.

### Smaller package, no source map ([#165](https://github.com/CLDMV/gh-broker/pull/165))

The build passed `--sourcemap`, and `files` shipped all of `dist/`, so every release carried a 1.4 MB `dist/index.mjs.map` that nothing used. The map is still built for local debugging, but `!dist/**/*.map` keeps it out of the package.

The build is now tsup, set up like the other CLDMV packages: one minified `dist/index.mjs` with function and class names kept, and every dependency still inlined, since the installer copies only `dist/` to `/opt/gh-broker`. `prepack` runs the build. The unpacked package goes from 3.2 MB to about 780 kB, and `dist/index.mjs` from 1.1 MB to 557 kB.

### Node.js floor back to 22.0.0 ([#162](https://github.com/CLDMV/gh-broker/pull/162))

`engines.node` is `>=22.0.0` again, the floor of `@octokit/request`. The `>=22.12.0` set in v0.3.2 was only ever for the vitest 5 test toolchain. That requirement now lives in `devEngines` (`>=22.22.0`), which npm checks only on the project's own installs, and in the CI and publish workflows' minimum Node version.

## Upgrade notes

- No breaking changes. Upgrade with `sudo npm install -g --prefix /usr/local --ignore-scripts @cldmv/gh-broker@latest` and `sudo gh-broker install`, then restart Claude sessions (or `/mcp` reconnect) so they pick up the restarted broker.
- Sessions using another config folder in the agent's home are found automatically. For a folder outside the home, run `sudo gh-broker agent sync <user> --claude-config <dir>` once.
- Anything that passed an unknown flag to a `gh-broker agent` subcommand now gets an error.
