# gh-broker v0.14.2 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/0.14.2`

---

## Overview

v0.14.2 finishes the `agent reconnect` fixes from v0.14.1. Sessions drawn in 24-bit colour are read correctly, and `upgrade` no longer reports a failure when reconnect only skipped some panes.

---

## 🐛 Bug Fixes

### `agent reconnect` reads sessions drawn in 24-bit colour ([#239](https://github.com/CLDMV/gh-broker/pull/239))

v0.14.1 ignores dimmed text in the input box (Claude Code's prompt suggestion) by reading the screen's SGR codes. It treated the `2` in a 24-bit colour code (`38;2;r;g;b`) as "dim", so everything after such a code was ignored. In a session drawn in 24-bit colour the line under the input box vanished, and the pane read as someone typing. Text typed in a 24-bit colour could also have read as empty. Colour codes' own arguments (`38`/`48`/`58` followed by `5;n` or `2;r;g;b`) are now skipped.

### Skipped sessions don't fail `upgrade` ([#239](https://github.com/CLDMV/gh-broker/pull/239))

`agent reconnect` now exits 3 when it only skipped panes (someone typing, a dialog open), and 1 when a named agent user doesn't exist. `upgrade` treats 3 as finished: it lists the skipped sessions, says to rerun `sudo gh-broker agent reconnect` once they're clear, and exits 0. Before, it reported step 3 as failed.

Stale tmux sockets, socket files with no tmux server running on them, are now one count line per user instead of a line each.

Part of [#235](https://github.com/CLDMV/gh-broker/issues/235); its `--wait` retry isn't in this release.
