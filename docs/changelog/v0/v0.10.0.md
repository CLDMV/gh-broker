# gh-broker v0.10.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.10.0`

---

## Overview

v0.10.0 puts the risky write tools behind a one-time code from an authenticator app. A gated tool runs only when the call carries a current TOTP code, and the agent can't produce one: it has to ask. The first good code opens a five-minute window for that agent. Bad codes lock that agent out, and repeated lockouts hard-lock it until it's unlocked by hand.

To tell agents apart, every agent user now gets its own socket under `/run/gh-broker/agents/` instead of sharing one. A new `gh-broker` command manages agents and the OTP state, and the installer writes each agent's MCP config for it.

The release also adds eleven write tools. Eight of them are gated by default, and the GitHub Copilot coding-agent tools ship disabled. A built-in deny list refuses file writes, repository deletion and repository settings at config load, whatever the config says.

This is a minor release on 0.x with a few breaking changes: the socket path, the `gh-broker` command and one `npm_scaffold` argument. See [Breaking Changes](#-breaking-changes) and [Upgrade notes](#upgrade-notes).

---

## 💥 Breaking Changes

- **One socket per agent.** The shared `/run/gh-broker/gh-broker.sock` is gone. Each agent connects to `/run/gh-broker/agents/<user>.sock`. The installer rewrites each agent's `~/.claude.json` entry, but every running Claude session has to be restarted to reconnect. ([#147](https://github.com/CLDMV/gh-broker/pull/147))
- **The package `bin` is now the `gh-broker` command**, not the installer. `sudo npx @cldmv/gh-broker <agent-user>` becomes `sudo gh-broker install <agent-user>` (or `sudo npx @cldmv/gh-broker install <agent-user>`). `sudo node deploy/install.mjs` from a checkout is unchanged. ([#147](https://github.com/CLDMV/gh-broker/pull/147))
- **`npm_scaffold`'s npm one-time password is now `npm_otp`**, renamed from `otp` so it doesn't collide with the broker's own `otp` argument. ([#147](https://github.com/CLDMV/gh-broker/pull/147))
- **Eight write tools now need a code** (listed below). Set `"otp": false` on a tool's entry to turn its gate off. ([#150](https://github.com/CLDMV/gh-broker/pull/150))

## ✨ Features

### OTP gate for write tools ([#147](https://github.com/CLDMV/gh-broker/pull/147))

A tool marked `"otp": true` in `config.tools`, or gated by the built-in default, needs a current code from an authenticator app passed as the `otp` argument. Fixes [#143](https://github.com/CLDMV/gh-broker/issues/143).

- **Window.** The first good code opens a 300-second window for that agent. Later gated calls in the window send the same code.
- **Lockouts.** Five bad codes lock that agent out for ten minutes. Three lockouts within 24 hours hard-lock it until `sudo gh-broker otp unlock <user>`. One agent's lockout never affects another.
- **Seed.** The installer generates the TOTP seed and prints it once as a QR code, the base32 key and the `otpauth://` URI. It stores the seed with the PATs, where the agent can't read it. An existing seed is never overwritten. `gh-broker otp rotate` replaces it.
- **State.** Lock counters live in `/var/lib/gh-broker/otp-state.json` and survive restarts. The broker re-reads the file when it changes, so an unlock takes effect on the next call. A corrupt file counts every agent as hard-locked until `otp unlock --all` rewrites it.
- **Hard lock.** A hard lock blocks every tool except `otp_status`.
- **`otp_status`** (read) reports the gate: which tools need a code, open windows, bad codes, lockouts and the hard lock with the command that clears it. It works while locked, so a locked-out agent can still tell you what happened.
- The audit log records each gate outcome, lockout and unlock. It never records codes or the seed.

### One socket per agent and the `gh-broker` command ([#147](https://github.com/CLDMV/gh-broker/pull/147))

- **Per-agent sockets.** Each registered agent gets its own group (`gh-broker-agent-<user>`) and socket, so the broker knows which user is calling.
- **`gh-broker agent add|remove|list|sync`** registers agents, writes each agent's `~/.claude.json` MCP entry and smoke-tests its socket.
  - The entry is written atomically, keeping the file's owner and mode, with a `.gh-broker.bak` backup.
  - Symlinks, hard links and files the agent doesn't own are left alone.
- **`gh-broker otp status|list|unlock|rotate`** shows and clears lock state and rotates the seed. Unlocks are written to the journal along with the sudo user who ran them.
- **`gh-broker install`** runs the installer.
- **Global install.** The recommended install is now `sudo npm install -g --prefix /usr/local --ignore-scripts @cldmv/gh-broker`, followed by `sudo gh-broker install`. The service runs from `/opt/gh-broker`. `otp status` and `agent list` warn when the installed package and the deployed copy differ.

### Eleven new write tools ([#150](https://github.com/CLDMV/gh-broker/pull/150))

Fixes [#146](https://github.com/CLDMV/gh-broker/issues/146).

- **Ungated:** `update_pull_request_branch`, `request_copilot_review`, and the new `minimize_comment` verb, which hides or unhides a comment over GraphQL by node id, or by REST id plus type.
- **Gated by default:** `create_repository`, `fork_repository`, `merge_pull_request`, `pull_request_review_write`, `actions_run_trigger` and `label_write`, plus two new verbs:
  - `delete_branch` refuses the default branch, the flow branches, and any branch that is the head or base of an open PR, including PRs from a fork into its parent or root. It returns the deleted sha with a command to restore it.
  - `dismiss_alert` dismisses or reopens a code scanning, Dependabot or secret scanning alert. It never returns a secret scanning alert's secret.
- **Checked before the gate,** so a bad call doesn't spend a code:
  - `create_repository` and `fork_repository` require `organization`, and create also requires `private`. The organization picks the write PAT, so a fork runs on the destination's.
  - `actions_run_trigger` refuses `delete_workflow_run_logs`.
- **Copilot coding-agent tools ship disabled.** `create_pull_request_with_copilot`, `assign_copilot_to_issue` and `assign_copilot_to_issue_with_intent` stay off until a tool's entry has `"enabled": true`, and they're gated once enabled.
- **Upgrades keep your settings.** `enabled` works per tool like `otp`, and the installer keeps both across upgrades.

### Deny list ([#150](https://github.com/CLDMV/gh-broker/pull/150))

`src/denylist.ts` refuses tools the broker should never expose, whatever `config.tools` says. A config that lists one fails to load, and the error says why. It covers:

- file and git-object writes;
- repository deletion;
- repository configuration: rulesets, branch protection, variables and secrets, workflow permissions, security settings, webhooks, deploy keys, collaborators and environments;
- bulk issue closing.

It matches exact names, plus a write verb paired with a protected subject.

## 🔒 Security & supply chain

- The gate, the deny list and the per-agent sockets are the security changes in this release; they are described above.
- The write PAT needs more permissions for the new tools: Administration, Actions, Workflows, and read/write on code scanning, Dependabot and secret scanning alerts. Administration: R/W is broad: on its own it also lets the token delete repositories and change their settings. The broker never offers those, but the token itself can do them, so treat the write PAT accordingly. See [deploy/README.md](https://github.com/CLDMV/gh-broker/blob/master/deploy/README.md).

## Upgrade notes

1. **Upgrade the package:**

   ```sh
   sudo npm install -g --prefix /usr/local --ignore-scripts @cldmv/gh-broker@latest
   sudo gh-broker install
   ```

   From a checkout, run `sudo node deploy/install.mjs` instead.
2. **What the installer does:**
   - registers the existing `gh-broker-clients` members as agents;
   - switches `listen` to `agents:/run/gh-broker/agents`;
   - rewrites each agent's MCP config;
   - generates the OTP seed and prints it once. **Scan the QR code before closing the terminal.**
3. **Restart every Claude session** so it reconnects to its own socket.
4. **Add the new write-PAT permissions** listed above if you want the new tools to work. The tools are advertised either way, and GitHub refuses a call the PAT has no permission for.
5. **Rename the argument.** Callers of `npm_scaffold` pass `npm_otp` instead of `otp`.
