# gh-broker v0.13.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.13.0`

---

## Overview

v0.13.0 makes upgrading one command. `sudo gh-broker upgrade` runs the npm install, the new release's installer and a reconnect of every running Claude Code session in one go, under one sudo. The reconnect step is also available on its own as `gh-broker agent reconnect`.

`npm_scaffold` now notices a trusted publisher that npm has already expired and says what to do about it, and the core library has a host guide.

---

## ✨ Features

### `gh-broker upgrade` ([#225](https://github.com/CLDMV/gh-broker/pull/225))

`sudo gh-broker upgrade` runs three steps in order and stops at the first one that fails, printing the commands that finish the job by hand:

1. `npm install -g --prefix /usr/local --ignore-scripts @cldmv/gh-broker@latest`, or `@<version>` with `--version <v>`. The target has to be a semantic version, and so does the answer from `npm view`. npm runs from `/` against the public registry.
2. The newly installed binary's `gh-broker install`, with the same flags you gave `upgrade` (`--claude-config <user>:<dir>`, `--no-mcp-config`, …). The flags are checked before npm runs, so a typo fails without installing anything. A flag only the new release knows can be passed as `--flag=value`.
3. The new binary's `agent reconnect`, because the service restart drops every Claude Code session's MCP connection. `--no-reconnect` skips it.

"Already up to date" is checked against the deployed service, not just the npm package, so a run where npm finished and the install didn't still installs. `--force` reinstalls anyway.

The old two-command upgrade used to stop after the npm install when the second `sudo` couldn't prompt for a password. A single `sudo` avoids that.

### `gh-broker agent reconnect` ([#225](https://github.com/CLDMV/gh-broker/pull/225))

`gh-broker agent reconnect [<user>]` types `/mcp reconnect <key>` into every running Claude Code tmux pane of the registered agents, with the server key read from each agent's own `.claude.json`. `--dry-run` shows what it would send.

It only types into a pane when it's safe to:

- Claude is the pane's foreground job;
- Claude isn't busy;
- the input box is empty;
- the pane isn't in copy mode or synchronized.

Each pane is checked again right before sending, and every skipped pane is listed with the reason.

Every tmux call runs as the agent user (via `setpriv`, keeping its groups, with a UTF-8 locale and a 5 s timeout), never as root. Each tmux server is talked to with its own binary, found through the server's process, so a box with two tmux versions installed still works. A key that isn't safe to type blind is refused.

Resolves [#223](https://github.com/CLDMV/gh-broker/issues/223).

## 🐛 Bug Fixes

### `npm_scaffold` reports an expired trusted publisher ([#221](https://github.com/CLDMV/gh-broker/pull/221))

npm drops a trusted publisher that hasn't been used within 2 days of being added. `npm_scaffold` used to treat a lapsed entry as configured and send you on to a publish that then failed. It now recognises an expired entry: an `expired` flag, an expired status, an `expires_at` in the past, or a `created_at` more than 2 days ago. It returns `status: "expired"` with the trust step left to do and instructions to delete the old entry on the package's access page. Every successful result also mentions the 2-day window, so the first publish happens in time.

Resolves [#216](https://github.com/CLDMV/gh-broker/issues/216).

## Upgrade notes

- v0.12.0 has no `upgrade` command, so the upgrade to v0.13.0 uses the old two commands. Run them as two separate lines in a terminal, so the second `sudo` can ask for a password:

  ```sh
  sudo npm install -g --prefix /usr/local --ignore-scripts @cldmv/gh-broker@latest
  sudo gh-broker install
  ```

  Then reconnect the running sessions with `sudo gh-broker agent reconnect`. From v0.13.0 on, `sudo gh-broker upgrade` does all of it.
- No config or library API changes.
