# gh-broker v0.10.6 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/0.10.6`

---

## Overview

v0.10.6 is a second fix for `npm_scaffold`. The v0.10.5 placeholder, `0.0.1-stage`, still collided with npm's staged publishing. npm answered the publish with 2xx, but the version never went live, so the trusted-publisher step had nothing to attach to. The placeholder is now `0.0.1-placeholder`, and the verb checks that it's actually on the registry before it reports the publish as done.

The only runtime change is in `npm_scaffold`.

---

## 🐛 Bug Fixes

### `npm_scaffold` no longer uses the `-stage` suffix ([#189](https://github.com/CLDMV/gh-broker/pull/189))

npm's staged publishing reserves `0.0.0-stage` for its own placeholder, which is why v0.10.4's placeholder was refused with 403. v0.10.5 moved to `0.0.1-stage`. npm accepted that PUT with a 2xx, but the package stayed 404 and `npm stage list` was empty. The next call tried to publish again and got `409 Cannot publish over previously staged version "0.0.1-stage"`.

The placeholder is now `0.0.1-placeholder`. After the PUT, the verb reads the package back from the registry's primary copy. If the placeholder isn't there, it fails with npm's answer and says the version may have been staged, instead of returning `needs_otp` for a trust step that can't work.

Fixes [#188](https://github.com/CLDMV/gh-broker/issues/188).
