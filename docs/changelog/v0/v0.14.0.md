# gh-broker v0.14.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.14.0`

---

## Overview

v0.14.0 adds `report_custom_properties`, a read tool for repository custom property values. It answers questions like "which repos have `branch-model` set to `v4`", which the search API's `props.` qualifier doesn't answer through the broker.

The CLDMV read PAT needs a new permission for it, see the upgrade notes.

---

## ✨ Features

### `report_custom_properties` ([#232](https://github.com/CLDMV/gh-broker/pull/232))

- With `repo`, it reads that repo's values (`GET /repos/{owner}/{repo}/properties/values`).
- Without `repo`, it lists every repo in the org (`GET /orgs/{org}/properties/values`, paginated). `repositoryQuery` is passed through as GitHub's `repository_query`.
- `property` keeps only repos where that property is set and reports just it. `value` also requires that value, and for a multi-select property matches any of its values.

Each repo comes back as `{ repo, properties }`, where a value is a string, an array of strings or `null`. The org listing is capped by `maxRepos` and `maxApiCalls` and returns `truncated: true` with a reason instead of failing. A 403 says which "Custom properties: read" permission the read PAT is missing.

Resolves [#231](https://github.com/CLDMV/gh-broker/issues/231).

## Upgrade notes

- Add **Custom properties: Read** to each owner's read PAT: the repository permission, plus the organization permission for the org-wide listing. Without it the tool returns a 403 naming the missing permission; nothing else is affected.
- `sudo gh-broker upgrade` from v0.13.x. From v0.12.0 or older, run the two install commands from the [v0.13.0 notes](./v0.13.0.md#upgrade-notes) first, as separate lines.
