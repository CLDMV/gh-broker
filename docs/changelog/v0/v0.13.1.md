# gh-broker v0.13.1 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/0.13.1`

## Overview

v0.13.1 fixes `report_release_changes` failing on any release that contains a PR merged with a merge commit whose branch commits mention an issue number. Nothing else changes.

---

## 🐛 Bug Fixes

### `report_release_changes` no longer fails on an issue number ([#228](https://github.com/CLDMV/gh-broker/pull/228))

A PR merged with a merge commit brings its branch commits into the release range. A branch commit whose subject ends in an issue number, such as `(#223)`, looks the same as a squash commit, so the verb looked it up as a PR. The lookup returned 404 and the whole call failed with `Not Found`. That happened on the v0.13.0 release PR.

A number that isn't a PR is now listed under `excluded` with reason `not-a-pr`, and the rest of the report comes back as usual. Any other error from a PR lookup still fails the call.

Fixes [#227](https://github.com/CLDMV/gh-broker/issues/227).
