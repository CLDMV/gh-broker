# gh-broker v0.17.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/0.17.0`

---

## Overview

v0.17.0 makes `agent reconnect`, and so `upgrade`'s last step, quieter and easier to aim. Sessions already running the `connect` bridge are left alone, every line says which tmux session and folder a pane is in, and `--session` reconnects just the panes you name.

---

## ✨ Features

### `agent reconnect` only types into sessions that need it ([#264](https://github.com/CLDMV/gh-broker/pull/264))

A session whose MCP entry runs the `connect` bridge redials a restarted broker on its own, so typing `/mcp reconnect` into it was noise, and it was the main reason panes got skipped or waited on. `agent reconnect` now decides each pane from the running process tree, not from `.claude.json` (the file can already say `connect` while the session still runs the socat entry it started with). A pane whose Claude has a bridge child owned by the agent, with the bridge's exact command line, is listed as `already on the connect bridge` and isn't counted as skipped: it doesn't make the run exit 3, and `upgrade` doesn't print "some sessions were skipped" for it. Sessions still on socat, or with no broker process at all, get `/mcp reconnect` as before. `--all` sends to every Claude pane, the old behaviour.

Resolves [#251](https://github.com/CLDMV/gh-broker/issues/251).

### Pane lines name the session, and `--session` picks panes ([#262](https://github.com/CLDMV/gh-broker/pull/262))

Every sent, skipped, waiting and dry-run line now shows the pane's tmux session and working directory after its id, e.g. `%77 (main, /home/repo) github skipped (…)`, including the lines a `--wait` prints. Both come from the agent's tmux, so control characters are blanked before printing.

`--session <name|%pane>` (repeatable) limits a run to the panes whose tmux session name or pane id matches exactly, so a single skipped pane can be retried with `sudo gh-broker agent reconnect repo --session %77`. It works with `--dry-run` and `--wait`; a value that matches no pane is reported and the run exits 1.

Resolves [#261](https://github.com/CLDMV/gh-broker/issues/261).

## Upgrade notes

- `sudo gh-broker upgrade`. This upgrade's own reconnect step already uses the new targeting, so sessions on the bridge are listed and left alone. Use `sudo gh-broker agent reconnect --all` if you want the old behaviour.
